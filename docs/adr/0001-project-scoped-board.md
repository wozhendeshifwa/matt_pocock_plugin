# 看板入口全局可用，内容按项目隔离

看板入口在 Codex 桌面端全局可用，目标位置是右上角 `+` 菜单对应的右侧区域。任务卡和任务会话进度归属项目，同一项目内切换聊天时继续显示，切换项目时自动显示目标项目的 Issues 和任务进度。这样用户无需回到原聊天找任务，也能明确知道派发动作针对哪个项目。

验收时先在 Windows Codex 桌面端检查侧栏入口，再用同项目的两个聊天和另一个项目验证上述行为。右侧栏接入方式以客户端实测为准。

原生右侧栏是首版发布门槛。需验证入口不依赖某条聊天消息，且打开看板后可与聊天并排工作。

2026-11-06 的 Windows 客户端实测已打开原生侧栏中的探针标签页。首次尝试显示加载错误。面板渲染和跨聊天保留仍待验证。

补上 MCP Apps 界面握手后，用户手测反馈探针功能基本无误。此结果验证的是侧栏探针。真实 Issues 加载、任务派发、进度回显和跨项目数据隔离仍需用实际看板验收。

用户截图确认，自动重启后，MattSkillsDeck 原型可在原生右侧栏渲染，并显示绑定仓库没有打开的 Issue。已验证真实仓库的空列表路径。非空列表、派发、进度回显和项目切换仍待验收。

验收 Issue #1 已通过后端闭环。看板读取真实 Issue、生成预览、派发只读任务，独立 Codex 会话完成，MCP 状态接口返回会话 ID 和结果。桌面端实际点击派发和跨项目切换仍待验证。

切换新聊天时，桌面日志显示看板资源请求收到 `Unsupported request`。服务此前只接受当前版本的资源地址，导致不同版本的客户端缓存与服务实例无法互通。看板改用稳定资源地址，并兼容已发布的 v3、v4 地址。已用两个独立服务进程验证三种地址，桌面端跨聊天回归待确认。

2026-11-06 自动重启后，用户确认原版 MattSkillsDeck 的结构符合预期。随后确认视觉要求：侧栏背景必须随 Codex 主题实时变化。适配层优先使用 Codex 注入的主题色变量，并以宿主 `light`/`dark` 信号作为兜底；不能用固定深色或仅跟随操作系统来冒充 Codex 主题同步。

2026-11-07：port 的派发保留宿主草稿语义，任务卡/独立任务会话与结果回显仍归旧 probe；边界见 ADR-0002。

2026-11-07：`#8` 确认 Codex 只支持 MCP Apps 的 `global` / `thread` / `file` 三种入口；port 当前使用 `thread` 入口。ADR 要求的全局入口是否对裸 `mcp_servers` 生效尚未验证，由地图 `#23` 做真实桌面探测；若 `global` 只对插件安装的服务开放，首版入口形态需要重新评估，不能把 `thread` 入口直接当作 ADR 已满足。
2026-11-07：项目身份解析落地为 `state_5.threads.cwd` 优先、rollout 首行只作旁证；cwd 必须落在已知项目根内，项目外 cwd（projectless 任务目录）一律 fail closed，不挂载、不沿用上一个项目。同一项目按 project root 共享看板。自动化证据见 #11；真实桌面四场景仍归 #15。
2026-11-07：#23 在 Windows Codex 桌面端 `26.1103.4239.0` 实测：裸 `mcp_servers` 声明 `global` 不产生主侧栏条目；本地 Codex 插件安装后主侧栏仍无条目，插件详情页的 `打开插件` 只能开出不带 `threadId`/`cwd` 的全屏 App 视图。首版入口因此确定为 `thread`，ADR 的「全局入口」要求记为宿主限制，不再作为首版发布门槛；若宿主未来开放本地插件侧栏固定，再评估「global + 显式项目选择器」。证据见 `docs/research/codex-global-entrypoint.md`。
