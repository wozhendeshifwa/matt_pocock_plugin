# #92 原生验收发现后的列表反馈与复制权限修复

基于 `codex/issue82-integration@364b0ed`，独立工作树 `native-layout-fix`。本记录只覆盖两项已复现差距，不把代码、受控布局或权限声明当作原生成功。

## 原生发现与最小修改

协调者在真实候选 MCP App（Codex 26.1120.6357.0）观察到：当前聊天必要条件未核验时正确停止，原手写草稿保留，但列表中四个技能的完整阻塞诊断与复制错误将动作区撑宽。视口 589px 时行 clientWidth／scrollWidth 为 549／2234，状态区宽 2172；详情动作区当时为 550／550，未复现该溢出。

只调整上游列表聚合行及地图任务行的动作父容器：从不可收缩的 `flex:none` 改为可收缩并限制最大宽度，显式恢复正常文本换行。共享直接动作组件和详情动作区样式均未改变；没有截断原因、隐藏错误或重建旧面板。

真实指针点击复制后仍收到 `Clipboard: Write permission denied`。当前宿主安装包的资源内容 schema 支持 `_meta.ui.permissions.clipboardWrite: {}` 并映射 `clipboard-write`，而服务此前只返回 URI、MIME 和 HTML。资源内容现仅声明剪贴板写入，未申请读取或其他设备权限，未改系统／全局权限或使用私有桥接。权限契约与资产共同参与资源 URI 的内容修订，避免旧 URI 缓存缺少声明的资源；旧资源别名返回相同声明。宿主是否接受声明、实际复制是否成功，仍须协调者原生复验。

## Red → green 与实际检查

- 原生列表的溢出是布局 red。JSDOM 没有布局引擎，不将样式字符串或零宽度断言当几何证明。
- 公开 `resources/read` 契约回归先失败：`contents[0]._meta` 为 `undefined`，应为仅含 `clipboardWrite` 的声明。补声明后通过，主 URI 和旧别名均核对，资源身份包含权限契约。
- 现有生产侧栏高层用例扩展为列表／详情的长四技能诊断与复制拒绝：每项原因完整保留，复制失败不覆盖原诊断，重试仍可用，没有宿主填入或复制成功。未放松必要条件守卫。
- 构建、`verify-direct-issue-actions`、`verify-direct-recovery`、`verify-bottom-action-bar`、`verify-more-issue-actions`、`verify-sidebar-resource-revision` 均通过；差异卫生检查通过。没有无理由重跑未受影响全量模块。
