## 范围

- 列表及详情的主入口明确命名“填入当前聊天”，正常来源经后台准备和再次核验后直接请求宿主，不挂载中转编辑器。
- 同组提供主动复制，使用同一份生成文本；已有旧草稿文本和来源审阅状态不被直接动作覆盖。
- 缺必要来源／条件先停止，来源变化先停止旧文本；复杂的明确再生成流程留给 #88。
- 原生回执只显示已请求；只有声明可靠能力的出口确认才显示已填入；未知和失败分别反馈并保留生成文本。
- 当前出口不可用时，点击前即可看到原因，主动复制仍可用。
- 旧预览暂由原新会话入口与底栏显式打开，保留既有恢复／编辑保护回归；#87 接新聊天，#91 才最终移除旧面板。

## TDD 与高层接缝

使用已确认的生产侧栏 UI → 来源准备／宿主草稿／剪贴板边界，外部来源与宿主为受控替身，没有通过内部状态或 DOM 私有实现断言确认业务结果。

1. 首个红灯：新增生产 UI 场景在 `the primary action must be explicitly named and directly available` 失败，原主按钮仍只开旧编辑器。实现直接入口后列表／详情与同文复制绿灯。
2. 第二个红灯：缺能力场景在 `unavailable direct output explains its reason before a click` 失败，原因只有悬停说明。增加可见原因后绿灯。
3. 同一高层脚本共 13 个场景：列表／详情正常直填同文复制、不可用出口主动复制、必要资料缺失、来源变化、可靠确认、未知回执、明确失败后的主动取回。

定向检查已运行通过：直接动作、聊天出口可用性、来源变化审阅、标签动作策略、底栏、按项目／Issue 恢复及原生桥接。旧预览测试显式选择旧新会话／底栏入口，不再把点击主动作必开编辑器作为预期。

- 本轮没有点击真实宿主输入框或自动发送。受控宿主只观察完整请求文本，未用替身主动拼接空行来证明生产行为。
