# #87 新聊天直接填入：实施证据

基线为集成分支 `codex/issue82-integration` 的 `b3aa67d`，独立实施分支 `codex/issue87-new-chat`。根工作区预存修改、配置、旧服务及宿主草稿未改动。

## 交付范围

- 列表和详情的直接动作组提供“填入新聊天”，经过与当前聊天相同的来源准备／检查后请求新草稿，不打开中转编辑器。
- 原生请求分别携带来源注册项目与来源实际 `cwd`，不再把注册项目根当作工作树／子目录。复核身份同时比较实际目录，目录变化时停止旧请求。
- 新聊天能力通过动态 getter 读取当前身份；缺项目身份、实际目录或链接能力时，按钮禁用并直接显示原因，主动复制保留。工厂创建时尚无身份，不会把不可用状态永久冻结。
- 由新聊天请求引起的正常导航不被返回后检查误判为意外切换。原生空回执仍为 `requested`，不升级为可靠填入，也不发送消息。
- 正常复制与新聊天请求使用同一份完整生成文本，参数中的中文、空格和特殊字符正确保留。
- 旧的独立“新会话”入口实际上打开旧编辑器，现明确改名“旧草稿预览”作为临时兼容入口，供 #91 最终删除；旧回归改为显式选择这一入口，不删除历史状态。

## TDD 证据

使用已确认的生产侧栏 UI → 来源准备／原生草稿适配器／外部宿主请求及剪贴板边界。没有新增私有状态或低层实现接缝。

逐条 red → green：

1. 原直接动作组没有新聊天入口，失败于 `the Issue action group must directly offer a new host draft`；新增实际入口后通过。
2. 来源实际子目录被替换为项目根，独立字面目录预期断言失败；改为实际 `cwd` 后通过。
3. 缺项目身份仍允许点击，失败于 `missing source identity or link capability disables new-chat injection before a click`；动态能力判定与可见原因后通过。
4. 复核实际目录改变后仍发请求，失败于 `a changed actual source directory stops the old new-chat request`；身份比较纳入 `cwd` 后通过。
5. 旧编辑器入口仍以“新会话”出现，失败于 `the old editor entry must not masquerade as the new-chat direct action`；兼容入口明确改名后通过。

新高层场景按列表／详情参数化，共 18 组：项目根、项目子目录、独立工作树、正常新聊天导航、工厂初始化身份晚到、缺项目身份、缺实际目录、缺链接能力、复核目录变化。高层测试使用真实生产 UI 和真实原生适配器，只有外部来源、宿主请求和剪贴板为受控边界；不通过测试替身拼接输入框来伪造生产追加。
