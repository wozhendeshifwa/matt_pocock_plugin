# AFK 工厂：质量门与返工决策

关联：[确定检查、独立审查与两轮返工的停机规则](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/114)。

以下是 AI 根据用户预先授权作出的决定，不是实时用户讨论或原生验收。此文定义后续产品契约，不表示现有产品已实现。

## 质量门

每张工单绑定验收条目、批准的输入版本、基线提交、输出提交和必需检查。首次实现为第 0 轮，之后最多两轮返工：第 1 轮、第 2 轮。检查与审查共用此预算，不能各自获得两轮。

1. 执行者在隔离工作区完成修改，保留完整差异、命令、退出码、日志及验收条目对应证据。
2. 确定性检查负责构建、类型、测试和项目必需检查；检查退出码缺失、容器消失或超时为未知，不能算通过，也不能冒充代码断言失败。
3. 独立审查者用新代理上下文，对比批准规格和输出差异，检查正确性、回归、仓库标准及验证缺口。审查必须绑定同一个输出提交与基线。执行者自评不算独立审查；无法取得独立审查者时进入待审查，不能降级通过。
4. 检查通过且独立审查无阻断发现，验收证据齐全，才进入可审阅。若工单要求原生验收，缺失该证据不得标记已验收；模拟与浏览器夹具不能替代原生证据。
5. 合并后的集成提交重新做必要集成检查；基线或输出改变使旧检查和审查失效，需按影响重新验证。产品“可审阅”不意味着已合并、发布或用户验收。

## 返工与停机

| 事件 | 动作 | 计数 |
|---|---|---|
| 第 0 轮检查失败或审查有阻断发现 | 汇总同一轮全部已知问题，进入第 1 轮返工 | 消耗一次 |
| 第 1 轮仍失败 | 进入第 2 轮返工 | 再消耗一次 |
| 第 2 轮仍失败 | 停止该工单，标记返工耗尽，交付现场与最小建议 | 不再自动实现 |
| 网络/工具中断，未知结果 | 先查询原执行是否仍运行，再按执行标识对账 | 不消耗代码返工；不得盲目重启 |
| 临时基础设施失败且证明原执行已结束 | 每阶段最多一次恢复尝试，仍未知即真实受阻 | 不开启无限重试 |
| 需求含糊、新权限/费用、范围改变 | 暂停相关工单及依赖它的工作，给出具体待决点 | 不消耗返工 |
| 用户取消 | 停止新步骤，确认执行终止、保留现场；终止未确认则保持未知 | 不自动恢复 |
| 审查证据格式不完整 | 每阶段最多一次补取，仍无效则待审查 | 不算“无发现” |

轮次在实现修改前持久预留，重复投递同一轮次不再增加计数；输出变更后必须重新检查与审查。预算耗尽后不可通过换代理、重新开任务或重置轮次自动绕过；恢复需要新的明确授权及可追踪记录。纯环境恢复不应重做已完成的代码修改。

阻断发现包括可复现错误、违反规格/仓库要求和必需证据缺失。建议性改善可记录为非阻断项，不自动扩大范围。系统记录判断依据，避免把所有建议都变成自动返工。

## 失败现场与结果汇总

每轮保存：批次/工单/执行/轮次标识、规格快照、基线和输出提交、工作区/沙箱标识、差异摘要、检查命令与退出结果、独立审查报告及审查者标识、发现与处理映射、停止原因、恢复前置、时间和证据位置。日志不含密钥；未知字段明确标未知。保留策略在用户确认结果前不得清除唯一可恢复现场。

汇总按工单展示“可审阅 / 返工耗尽 / 等待决定 / 待审查 / 执行结果未知 / 已取消”；展开显示当前轮次、上次有效证据、依赖影响和下一步。批次可以部分交付，禁止把部分成功汇总成全部成功。

## 反例验算

- 首轮测试失败、下一轮测试成功但审查失败：已经用了第 1 轮，下次只能第 2 轮。
- 检查输出最后一行写着成功但无正常退出码：未知，不进入可审阅。
- 第 2 轮通过后审查发现越权修改：返工耗尽并停止，不能用第三个代理继续改。
- A 等待凭据，B 无依赖：A 局部暂停，B 可继续。
- 检查通过后文件再被修改：旧通过和旧审查不能用于新输出。
