# MattSkillsDeck × Sandcastle：AFK 软件工厂首版方案

关联：[规划 MattSkillsDeck 与 Sandcastle 的 AFK 软件工厂](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/112)。

AI 根据用户预先授权作出的决定。本文交付产品与技术方案；软件工厂产品尚未实施，真实沙箱端到端与 Codex 原生验收尚未进行。

## 目的地与首版体验

用户选择一批明确工单，预览并确认固定的范围、基线、依赖和执行参数。系统并行处理独立工作，串行处理冲突和依赖；执行、检查、独立审查失败时最多两轮返工。每单最终交付可审阅代码或带证据的停止原因。局部等待不停止独立工作。首版的默认终点是用户审阅，合并与发布需要用户另行确认。

本地图只完成规划与合成试点，不能用本次合并规划文档的授权作为未来工厂自动合并的授权。

## 术语

以下术语仅用于本规划，不改写源目录已有的 GLOSSARY 用户改动。

- **批次**：用户一次确认、具有固定接单快照的一组工单。
- **执行**：绑定某单输入版本、基线及隔离环境的一次运行；重查不创建新执行。
- **返工轮次**：首次实现后的修改预算，检查与独立审查共用，最多两轮。
- **可审阅**：输出提交具有必需检查、独立审查和验收证据，等待用户审阅；不意味着合并或发布。
- **未知**：无法证明原执行或检查结果；需对账，不视为成功或可安全重跑。

既有“提示词注入”仍仅指填入宿主草稿，不能称为已经派发或开始执行。

## 职责边界

| 层 | 首版职责 | 验证界限 |
|---|---|---|
| 提示词与主代理 | 解读明确规格、选择批内顺序、生成执行/审查输入、解释发现和汇总证据 | 可做有人监督/当前会话的低成本试点；不能保证会话结束后继续运行 |
| Matt 插件后台 | 保存确认快照、依赖/冲突图、认领租约、稳定执行标识、轮次及证据索引；调度、取消、恢复和项目隔离；展示真实状态与待决点 | 这些是拟实施能力；现有插件草稿按钮不等于持久调度 |
| Sandcastle 执行层 | 单任务隔离、固定基线、受限工具运行、检查、日志与结果差异；暴露真实执行与停止证据 | 复用已有单任务能力，但需确认每个实际适配接口；不承担产品需求判断、批次授权或用户验收 |
| 独立审查代理 | 在新上下文中读取批准规格与固定差异，报告阻断发现和验证缺口 | 绑定输出SHA，不以执行者自评替代；不可取得则待审查 |
| 用户 | 确认批次、处理未授权变化/新凭据或费用、审阅结果，决定合并/发布 | 不把AI常规取舍记成现场用户讨论 |

推荐“提示词先试点，持久后台作为无人值守产品首版必要条件”。理由是提示词适合便宜地暴露工作流遗漏，但丢回包、上下文结束和进程重启需要独立于模型记忆的状态事实。不能把人工复制检查点包装为可靠后台恢复。

这条后续产品路线将重新评估 [草稿语义 ADR](../adr/0002-prefill-dispatch-boundary.md) 中“不在 port 内建第二套任务引擎”的范围；本地图只记录建议，不静默覆盖 ADR 或改变现有按钮。后续实施需独立入口、显式确认和 ADR 取舍，保留既有提示词注入语义。

## 持久协议与恢复

确认快照包含项目身份、工单版本、输入摘要、授权依据、依赖图、冲突区域、基线、验收与检查命令、资源及费用边界。写入成功后才调度。模型可提出计划，但持久协调者校验每个状态转换。

启动以稳定操作标识写入待执行记录，再调用执行层。回包丢失后查原标识及执行身份，不能直接再创建；若跨层无法证明幂等，就停为未知并展示最小核实动作。不要承诺通用“恰好一次”。租约到期仅触发核实，不证明旧进程已停止，也不自动释放资源。

每轮在修改前预留预算，绑定输入版本和输出提交；查询重复不加轮次，重启不清零。检查和审查证据绑定基线及输出，内容变化则失效。集成在隔离分支串行进行，后继用已核实集成SHA启动；最终集成失败仍不能标记整批可审阅。

恢复先核对项目、批次、授权、输入、遗留进程和实际输出；仍运行则接回观察，已停止才继续，未知则仅阻塞该执行和实际依赖者。人工暂停/取消不得自动恢复。整体用户停止优先于自动接续。状态恢复不自动重开已耗尽的返工预算。

## 结果界面与用户介入

批次总览显示每单名称、状态、轮次、依赖、检查/审查摘要、输出提交、最后更新时间和证据入口。展开显示全部失败轮次、差异、阻断原因及最小下一步；可审阅与未知/耗尽/待决分组计数，部分成功不得显示全部完成。

等待卡只询问真正缺少的决定，展示变化和影响范围；其他独立工单继续。重试/恢复前显示原执行及已用预算；取消保留唯一现场；合并和发布与查看结果分开，禁止“查看”隐式执行写入。

## 首版验收矩阵

以下均为后续实施必需场景，不是本次已通过结果。

| 场景 | 通过证据 |
|---|---|
| 两张独立单、一张依赖单 | 各自隔离执行记录；并行符合容量；后继基于核实集成SHA |
| 同改锁文件/共享配置 | 串行锁及后单基线，无共享覆盖 |
| 检查与审查轮流失败 | 共享计数0→1→2，第三次失败停止，无隐藏第三轮 |
| 执行成功回包丢失/重复点击 | 同稳定标识查询同一执行；未知时不重复创建 |
| 检查无退出码/执行层断线 | unknown而非passed；资源占用与实际执行核实 |
| 主会话结束/后台重启 | 状态、暂停、轮次、证据仍在；恢复先对账，不重复运行 |
| 一单等凭据或范围确认 | 相关依赖等待，独立单继续；未新增权限/费用 |
| 审查缺失或输出随后改变 | 不进入可审阅；旧证据失效并显示缺口 |
| 用户取消/整批暂停 | 核实终止才释放资源；重启不自动恢复；代码日志保留 |
| 两单分别通过但集成失败 | 批次未完成，保留单项及集成失败证据 |
| 不同项目同时运行 | 项目身份校验与隔离；结果、恢复及取消不跨项目 |
| Codex真实界面入口至结果 | 确认目标项目/聊天、保留草稿；预览与实际执行一致，状态及差异读回；恢复临时UI设置 |

采用固定小型合成仓库做故障验收，随后以用户确认的 Matt 插件小任务试运行。先验证环境和费用边界，不能因本方案存在就启动生产工单。

## 实施交接顺序

1. 核对现有单任务执行接口和故障验收入口，完成独立调度入口的规格及ADR评估。
2. 实现接单快照、持久状态/标识、恢复对账和项目隔离；先过重复启动、重启与取消场景。
3. 实现依赖/冲突调度与共享返工预算，接入真正独立审查，过局部暂停及集成场景。
4. 实现结果总览与必要介入，再做 Codex 原生端到端与用户确认的小任务试运行。

每阶段需独立明确实施规格与票图；本地图不自动接纳生产工单。部署、发布及新增费用/凭据仍需对应授权。
