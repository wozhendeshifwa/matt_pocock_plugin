## 已安装 Codex 的原生调用

用桌面同版本的独立 app-server 进程接入已安装的远程插件。使用四个真实聊天，在协议的 `threadId` 参数选择目标聊天，由 Codex 向 MCP 传递身份。程序没有传入 MCP `_meta`、伪造项目根或发送聊天消息。测试先检查聊天标识与预期项目根，再核对两个拒绝场景。首次选到一个已被桌面占用的聊天，保留原锁，改用另一空闲聊天。

| 顺序 | 场景 | 实际结果 |
| --- | --- | --- |
| 1、2 | 同项目的两个不同聊天 | 两次均返回各自的聊天 ID 和同一项目根 |
| 3 | 另一个项目的聊天 | 返回该聊天 ID 和另一个项目根 |
| 4 | 切回第一个聊天 | 再次返回最初的聊天 ID 和项目根 |
| 5 | 无关联项目的聊天 | 明确拒绝访问，没有沿用上一个项目 |
| 6 | 在第一个聊天中提交带有另一聊天标识的 Git 状态请求 | 因聊天标识过期而被拒绝 |

上述结果验证原生调用的身份路由。可视窗口跨聊天后面板的刷新仍需单独观察。

## 复验方法

从本机真实聊天中选取三个已关联项目的空闲聊天及一个无关联项目的空闲聊天。在本地临时目录建立 JSON 文件，字段为 `first`、`second`、`other`、`unscoped`。每个字段的值包含 `id`。前三项还需提供本机核实的绝对项目根 `cwd`，前两项属于同一项目，第三项属于不同项目。私人聊天标识和目录仅放入本机临时文件。

在远程插件已启用、已有 caller 凭据环境的 PowerShell 中，将第一行替换为本机用例文件的路径并运行。

```powershell
$casesFile = 'C:\Temp\deck-routing-cases.json'
node prototypes/remote-companion/acceptance/verify-desktop-routing.mjs $casesFile (Get-Command codex).Source
```

成功时输出四行聊天及项目匹配、两行拒绝结果，退出码为 0。对尚未加载的聊天，脚本请求恢复会话，指定响应省略历史轮次。遇到其他进程占用的聊天会失败退出，可选另一空闲聊天复验。
