# 全插件原生融合视觉候选规格

日期：2026-11-28。对应[通过整体原型确定与 Codex 融合的视觉规范](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/102)。状态：主代理已在本机Chrome审阅A/B/C及A浅色详情，选定A（AI根据用户预先授权作出的决定）；不是产品实现或原生验收结论。

## 方案与依据

读取同日 native-visual-live-baseline、host-followup、baseline-completion、inventory 记录。宿主已注入真实 `--color-*`，插件仍主要读取旧别名并落到蓝黑兜底；技能详情显示羊皮纸，版本管理焦点固定蓝色。这些事实指导设计，不是闪烁根因。

原型是 `prototypes/upstream-port/native-visual-prototype.html`，直接用浏览器打开。URL `?variant=A`、`B`、`C` 或底部左右切换器选方案；方向键在编辑框及弹窗内不被截获。主题/320宽度仅是原型预览，不冒充宿主验收。单文件假数据，不接服务、不持久化、不被产品构建引用；应由主代理捕获到抛弃式分支，不把原型直接合入产品。

| 方案 | 呈现 | 取舍 |
| --- | --- | --- |
| A，推荐 | 宿主中性色、轻分层卡片、克制边界 | 保留任务/地图层次，密度适合侧栏，与宿主邻接协调 |
| B | 平面清单、行分隔、减少容器边界 | 更紧凑，但长内容分组和地图层级较弱 |
| C | 宽松表面、大间距和较大按钮 | 宽栏舒展，320栏滚动成本高 |

AI 根据用户预先授权作出的推荐：采用 A，窄栏局部允许 B 的紧凑间距。用户要求保留信息架构，因此方案不为了结构差异而重排导航或功能流程。未声称用户参与现场选型；最终由主代理审查记录决议。

## 基础契约

保留现有 `--dsw-alias-*` 作为内部接缝，读取顺序为宿主真实 `--color-*` →现有兼容别名→明暗中性兜底。仅改呈现，不改主题同步事件、时序、超时和桥接逻辑。

| 角色 | 首选宿主值 | 缺失时 |
| --- | --- | --- |
| 背景/主文字 | `--color-background-primary` / `--color-text-primary` | 兼容background/foreground后，白/#181818及深字/白字 |
| 容器/浮层 | background-secondary，必要时tertiary | 同一中性色系轻分层，不引入蓝黑、米黄或霓虹 |
| 次级文字 | text-secondary / tertiary | 主文字与背景混合产生仍可阅读的弱层级 |
| 边框/分隔 | border-primary / secondary | 1px明暗适配轻边界 |
| 焦点 | ring-primary | 对比明确的中性outline，不固定蓝色 |
| 成功/危险/警告/信息 | 对应text、background、border角色 | 各自语义色并保留文字/符号，不仅凭颜色区分 |

不把info当强调色，也不把紫色固定为所有宿主预设的按钮色。没有专用按钮角色时，主动作使用主体字色/基础背景构成中性反色按钮，焦点仍取ring。

系统字体优先 `--font-sans`；正文14px、工具栏/次级正文13px、标签/辅助12px，约1.5行高；标题16/18px。代码、diff、路径保留等宽字体。常规控件最小高30–32px，窄栏可紧凑但不压掉文字。圆角6px控件、8px容器、12px弹窗，1px边框，常规内容不叠装饰阴影。

悬停取主文字低比例混合背景；focus-visible为2px宿主ring，带间距。选中由背景/边界/文字或既有指示共同表达。禁用保留解释；加载、空白、错误及重试同一排版层次；减少动画偏好下关闭装饰动画。

## 全界面覆盖

| 页面/区域 | 统一方式与保留项 |
| --- | --- |
| 五顶层页签/外壳 | 宿主背景、系统字体、轻分隔；保留页签顺序与选中态 |
| 看板仓库栏/筛选/列表/规格子票/分页 | 工具栏和标签可换行；保留所有筛选、关系、双填入及反馈 |
| Issue/地图详情/评论 | 正文统一；地图保留层级、依赖、进度、折叠，移除霓虹与独立像素装饰 |
| 版本管理各子视图/页内确认 | 同一普通控件契约，保留Git状态语义；diff等宽局部横滚，长路径可滚动；禁用与操作语义不变 |
| PR列表 | 同一列表密度与状态标签，保留跳转和动作 |
| 技能列表/详情 | 详情移除羊皮纸、像素字体/边框；保留目录、来源提示、代码和长文滚动 |
| 环境检查 | 成功/进行中/缺失用文字与符号并列，保留能力诊断折叠 |
| 设置/日志/更新说明/后端总览 | 表单、辅助文字、链接同一契约；不改变调试、清空、更新与配置行为 |
| 状态/命名建议 | 同一文字和只读输入样式；不把只读建议变可编辑 |
| 运行 | 普通文字/按钮同一契约，保留现有入口和能力 |
| 沙箱任务 | 表单、模型/时限、任务列表/详情、日志/diff、预览/确认统一；保留执行/检查/合入区别 |
| 配色/后端选择与切换确认/schema表单/地图模式弹窗 | 同一浮层背景、边框、标题、关闭与焦点；不改字段/默认值/确认语义 |
| Toast/底部反馈/空白/错误/禁用 | 状态文字可换行且不遮唯一动作；不把错误文案视为调查结论 |

`+需求/+bug` 是新聊天草稿入口，不是创建表单。通用schema表单按实际动作链覆盖。版本管理和沙箱的部分确认属于页内区，不能全部套全局dialog。

## 响应式与内容保留

沿用已决最低有效CSS视口320×400。根不横向溢出；工具栏、动作、标签可换行/堆叠；正文和长标题保留语义。路径和diff各自局部横滚。宽栏增加内容宽度，不重排导航或关系。弹窗宽不超过视口减24px、限制高度并使正文可滚，标题/关闭可达。

200%必须记录宿主实际缩放值，DPR单独不能证明；已有319×366低于最低高度，是边界现状，不是320×400通过。候选仍须验证编辑、选择、折叠、滚动和焦点状态保留。

## 实现顺序与证据边界

1. 基础变量及普通控件契约；深/浅宿主变量受控覆盖检查。
2. 看板/地图/技能详情独立皮肤；保留IA和动作，逐页检查文字、溢出和弹窗。
3. 版本管理、沙箱、设置/状态/运行及剩余浮层；受控320×400、普通侧栏、宽栏/全屏，明暗、长内容、加载/空/错/禁用和键盘矩阵。
4. 对具体候选构建核对加载资源后执行原生静态验收。旧UI采集、原型和根不溢出都不能代替整体验收。

独立主题闪烁调查继续暂停；本规格不改主题时序、不复现或修复闪烁。动态最终条件和验收等待调查结论，静态设计、实现、审查与受控验证继续。发布、部署和运行入口切换仍须具体可审核版本及相应授权。

审阅：实际打开离线HTML，检查A普通/320示意、B/C窄栏及A浅色技能详情。A保留分组且窄栏成本低于C；采用A，窄栏借用紧凑间距。原型的320仅约束面板示意，不是实际320浏览器视口，弹窗在外层大视口中显示，不能当320弹窗通过。

未验证：无产品候选构建验收；未证明全部状态、精确320×400、所有预设对比度或原生状态保留。按独立工程票实施，不将本决策票当产品交付。
