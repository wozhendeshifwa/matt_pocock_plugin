# 提示词版 AFK 工厂：最小工作流试点

关联[原型：验证提示词版软件工厂的最小工作流](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/116)。2026-11-28，**AI 根据用户预先授权作出的决定**。本次使用本地 `prototype/SKILL.md` 和 `LOGIC.md`，依据接单与质量两个决策文档。它是规划用合成试点，不是实际模型/沙箱工单批次，也不是真人反馈、产品交付或原生验收。

## 原型问题与入口

原型保存在独立抛弃分支 `codex/afk-factory-prototype`，提交 `1b662c2b14c91ae7ccae42e5d0f2589b54c9ff88`，不进入默认分支。[查看或下载原型](https://github.com/wozhendeshifwa/matt_pocock_plugin/blob/1b662c2b14c91ae7ccae42e5d0f2589b54c9ff88/prototypes/afk-factory-workflow-prototype.html)，下载后双击打开即可。单文件无依赖、无请求、无持久存储。上方展示全部相关状态，中间可任意点击，下方六个导览各自重置初始状态；导览逐步点击真实动作。非法动作返回拒绝且不改变工单状态。

纯 `FactoryModel.initial/reduce` 与 DOM 分开。检查、独立审查、派发、回包丢失及恢复均是人点击模拟；执行身份也是模拟ID。模拟重启复制内存检查点，保留轮次和暂停，**不证明真实磁盘持久化、跨进程互斥或服务恢复**。真实页面刷新会重置。

## 三张合成工单的接单快照

共同字段：批次 `demo-1`；项目 `matt_pocock_plugin` 的模拟副本；固定模拟基线 `base-001`；规格版本 `spec-1`；只允许隔离实现、检查、审查与生成可审阅结果；不合并、不发布、不读取凭据、不发起费用；并发上限2；每单初次第0轮，检查与审查共用最多第1/2轮返工。真实试点必须把模拟路径/SHA换成实际字段并取得批次确认后才能执行。

| 工单 | 目标与排除项 | 依赖/冲突区域 | 验收与检查 | 结果 |
| --- | --- | --- | --- | --- |
| A：补充试点说明 | 在模拟副本添加最小操作说明；不改产品配置 | 无；模拟 `docs/demo-a.md` | 包含目标/步骤/边界，模拟文档检查，独立审查规格 | `A/output-vN`及轮次证据 |
| B：核对说明索引 | 在模拟副本更新索引引用A；不更改A目标 | 依赖A可审阅且取得模拟集成基线；模拟 `docs/demo-index.md` | 链接指向A，模拟链接检查，独立审查 | `B/output-vN`及轮次证据 |
| C：整理独立例子 | 在模拟副本新增独立例子；不修改A/B | 无；模拟 `docs/demo-c.md` | 例子满足声明输入/输出，模拟文档检查，独立审查 | `C/output-vN`及轮次证据 |

“用户确认”在模型中是预设前提，不声称真人已经确认这些未来真实任务。页面用A通过加“核实集成基线”作为B开工门槛，该证据绑定A当前输出版本；真实集成SHA、冲突分析、运行时限、费用和检查命令仍须由实际接单快照补齐。返工重新占槽也检查容量。“注入外部输出变化”是旧证据失效的故障场景，不代表允许预算外自动修改。

## 六个预期步骤与判断

| 导览 | 操作主线 | 预期结论 |
| --- | --- | --- |
| 正常交付 | 先尝试B；A实现→检查→审查；再次尝试B→核实集成基线；C独立通过；B通过 | B在依赖/集成证据缺失时被拒绝；三单可审阅且未合并未发布 |
| 共用两轮与耗尽 | 第0轮检查失败→第1轮检查通过但审查阻断→第2轮检查失败→再返工 | 返工轮次始终不超过2，第三次被拒绝 |
| 局部暂停 | 暂停A，尝试A/B；独立C完成 | A保持暂停，B排队，C可审阅 |
| 丢回包 | 开始A并丢回包→重派/取输出被拒绝→核实原执行→完成 | 启动次数1，不生成重复执行 |
| 输出变化 | A通过→修改输出→直接审查被拒绝→重新检查/审查 | v1旧证据失效，v2重新验证 |
| 重启保留 | 第1轮暂停→模拟重启→继续被拒绝→明确恢复→第2轮耗尽 | 暂停与预算不因重启清零 |

主代理已在独立 Chrome 临时配置中执行六组导览的实际 DOM 按钮，每组状态结果均符合上表；另验证容量满时返工被拒绝且不增加轮次，以及前驱变化后已启动后继无法直接恢复。截图已读回，三单正常完成路径展示版本绑定的检查/审查及 B 的前驱集成证据。此为浏览器内受控模拟，不是真实模型、沙箱或 Codex 原生验收。

本地原始证据：`.scratch/afk-factory-validation/results.json`、`normal-workflow.png`；独立审查的 VM 操作也复核了集成门、容量门与过期恢复拒绝。批次结果允许部分可审阅；失败单、待决单和未知执行分别展示，不把其余通过写作全批成功。

## 可复用协调提示词

以下是模板；方括号必须填实际事实，未填字段不能当作已确认。

```text
你是此批次的协调者。运行模板：[标准开发 / 持续批处理]。
批次：[ID]；确认记录：[用户实际确认/有效预先授权指针]。
项目/仓库：[实际规范路径与URL]；固定基线：[完整SHA]。
已确认工单：[逐单URL、规格摘要/版本、目标、排除项、验收标准]。
依赖：[原生依赖和产物前置]；冲突区域：[文件/服务/UI资源]。
执行容量：[不超过实际全机容量]；模型/时限/费用边界：[已授权事实]。
必需检查：[命令与退出码要求]；必需原生验收：[有/无及证据要求]。
结果操作授权：[例如仅可审阅，不合并、不发布]。
状态与证据位置：[每单/轮次/执行/输入/输出ID、日志和检查点路径]。

先核实以上字段及最新认领/依赖/实际运行，不猜测缺失授权。
只执行此批确认范围；实质缺项暂停该单及实际后继，独立单继续。
在不同隔离工作区并行独立单；共享改动、重启或原生UI资源串行。
启动前记下稳定执行标识和输入快照；回包丢失先查询原执行，不重派。
首次为第0轮，检查和独立审查共用最多两轮返工；修改前预留轮次。
检查和独立审查都绑定同一基线/输出；执行者自评不算独立审查。
输出或基线变化使旧证据失效。未知退出结果不能算通过或断言失败。
基础设施恢复每阶段至多一次；仍未知就保留现场并标真实受阻。
明确人工暂停/取消保持；恢复核实原执行、授权和预算，不重置轮次。
汇总每单：可审阅/返工耗尽/等待决定/待审查/执行结果未知/已取消。
每单给证据、影响、下一步；仅批准全部必要证据齐备的可审阅结果。
不把模拟、草稿填入、queued回执、单单通过或AI决策说成原生验收。
```

## 运行模板是流程预设

“运行模板”选择流程，不是视觉样式，也不是新授权。每次仍须绑定上面的实际字段、批次确认和预算。当前入口是否实际支持这些预设尚未核验；以下仅为方案。

| 预设 | 适用方式 | 本地图重点 |
| --- | --- | --- |
| 标准开发 | 单批实现→检查→独立审查→最多两轮返工→可审阅 | 默认试点；保留完整质量门 |
| 持续批处理 | 沿同一确认批次持续调度，局部暂停，独立单继续 | 核心；不自动接纳新工单 |
| 快速验证 | 小型问题/抛弃式产物，减少产物包装 | 不得跳过已要求的检查或权限 |
| 谨慎执行 | 更低并发，更多检查点和显式风险核实 | 不凭名称扩大/撤销原授权 |
| 仅检查审查 | 针对固定输出收集检查及独立审查，不修改代码 | 不自动进入返工 |
| 自定义 | 用户指定预设字段差异 | 超出已确认范围仍须新确认 |

首版先验证标准开发与持续批处理；不同文字呈现可以后另行探索，不扩为本次产品实现。

## 能力结论与后续拥有边界

提示词可以表达批次边界、协调顺序、人工暂停、质量门和汇总协议；在有工具与稳定会话的条件下，协调代理可按协议执行。提示词本身不提供持久队列、原子认领、运行身份核实、并发互斥、至多一次派发、后台存活、可靠唤醒或执行证据真实性。

因此本模拟只验证规则是否能清楚表达和按有限状态运行，不能作为“提示词版软件工厂已端到端可用”的证据。实际插件化职责及首版验收由[划定提示词、Matt 插件与 Sandcastle 的职责和首版验收](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/113)据实收敛。当前原型未调用真实模型或沙箱，也未测试宿主技能加载、真实独立审查、故障恢复或原生UI。
