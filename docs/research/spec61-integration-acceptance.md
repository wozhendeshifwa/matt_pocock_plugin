## 公开消费接口

实现：[request-preparation.mjs](../../prototypes/upstream-port/request-preparation.mjs)；实际接线：[browser-runtime.mjs](../../prototypes/upstream-port/browser-runtime.mjs)。

每个已挂载的项目面板有独立的 `requestPreparation` 服务。上游适配闭包通过 `ctx.get('requestPreparation')` 取得；宿主侧可以通过 `window.MattSkillsCodex.requestPreparation(rootElement)` 取得同一个实例。面板卸载会清理本实例及其会话内快照，不跨刷新保存。

### prepare({ text })

输入动作构造器已生成的基础请求，先完成技能使用前维护，再读取同一项目的技能详情及必要条件。返回：

| 字段 | 含义 |
| --- | --- |
| `id` | 本服务实例内的来源观察快照 ID；不是宿主收据、用户确认或实际加载证明 |
| `text` | 基础请求加上必要来源／更新说明的候选文本，交给现有可编辑预览展示 |
| `sourceNote` | 来源类型、路径、实际加载未知、更新状态、备用与缺项说明 |
| `names` | 文本中明确调用的受管技能 |
| `dependenciesAllowed` | 已观察必要规则、引用和工具是否满足；不表示任务已获授权或执行 |
| `mode` | `request` 或 `clarify`；缺项时请求仍可用于查证，依赖实施须暂停 |

这一步只返回候选文本，不填宿主、不复制、不发送，也不覆盖任何已有编辑。消费者负责把候选文本交给用户审阅，并按已确认的草稿替换保护规则处理脏编辑。

### check({ draftId, text })

在选定出口前传入快照 ID 和用户最终编辑文本，重新检查技能来源及更新。返回 `allowed`、`status` 和原样的 `text`。事实或技能集合变化时返回 `allowed:false`、`status:'review-required'`、新 `sourceNote` 及原因；原文完整保留，消费者必须停住旧出口并先更新可见预览／重新审阅。失效或跨实例快照也不能继续。

快照比较排除检查时间、下载计数等非行为字段；同一已核验 revision 的 `updated` 和 `up-to-date` 规范为相同事实，正文纯换行差异不触发重新审阅。来源路径、正文、必要工具／资料或绑定 revision 等实质变化会停止旧出口。

用户可以改写或删除已展示说明。来源事实及技能集合未变时，`check` 不要求旧说明逐字保留，不悄悄补回文字；最终文本始终由用户控制。此接口本身不证明用户看过预览。

消费者流程：生成基础请求 → `prepare` → 展示候选并允许编辑 → 选出口时 `check` → 仅 `allowed:true` 时把返回的原样 `text` 交给该出口。出口失败时保留编辑文本，不能自动改投其他出口。来源变化后的候选说明先交用户审阅；消费者不得以重新生成文本的方式静默丢弃用户编辑。

`check` 已做使用前维护；新消费者不应随后再走只接受 `(st,text)` 的旧 `codexPrepareSkillUse` 守卫，否则维护失败但已明确供查证的请求可能再次被旧守卫阻止。旧守卫仍用于尚未改造的入口，仍会停住变化的旧出口。实际可靠草稿读取、已有输入保护、目标变化及填入结果确认由交互／宿主出口消费者负责；本服务不伪造这些能力。

### 与正在实现的底栏对齐

只读查看的 `codex/issue64-bottom-bar` 原型消费者已有 `inspectSkill`、来源显示、可编辑文本和编辑确认；目前没有消费本接口的快照与检查结果。它需要用本服务替换自己的简化来源拼接及出口前旧守卫，保留已有布局、编辑保护和最终文本一致性。本分支没有修改其工作树，也没有把这项跨票集成写成已经完成。
