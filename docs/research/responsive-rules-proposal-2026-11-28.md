# 窄侧栏到全屏：响应式规则决议

服务于[确定窄侧栏到全屏的响应式与内容保留规则](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/104)。2026-11-28 接续源码建议稿，依据用户本轮“所有带输入部分保持静默，用户均确认或按推荐”的明确授权采用以下规则。此处记录设计决议，不表示产品已经实现或通过原生验收，也不声称用户逐项手测。

技能来源：使用 matt 插件 `issueActionRequest` 针对本票生成的 `$grill-with-docs` 提示词；没有可调用的宿主技能加载接口，已完整读取本地 `grill-with-docs/SKILL.md` 及其引用的 `grilling/SKILL.md`、`domain-modeling/SKILL.md` 作为只读备用。用户本轮自主决策授权优先于技能默认的逐轮提问要求。

## 已确认边界

- 全插件视觉更新以当前 Codex 为参照，保留页面、导航、功能分区和操作流程；允许换行、堆叠及局部折叠。
- 覆盖全部现有页面及弹窗、明暗主题、窄侧栏、宽侧栏和全屏。
- 保留现有两个提示词填入出口及底部短暂反馈；不自动发送，不恢复旧草稿中转面板或 More。
- 本聊天留在当前目录，不能为适配工作切换聊天工作目录。

## 采用的规则

| 范围 | 建议 | 用户得到的结果 |
| --- | --- | --- |
| 支持基线 | 以插件内部布局视口 320 CSS px 宽、400 CSS px 高为完整支持基线；更低高度解除大块固定区域并保留纵向访问路径；低于320宽度列为尽力适配，不承诺同等布局验收 | 在实际容器尺寸下检查，不把屏幕物理像素或桌面缩放直接当作布局宽度 |
| 尺寸样本 | 320、380、480、640、960 CSS px，以及宿主可达到的全屏宽度；宽度门槛依据内容拥挤程度调整，先不固化实现断点 | 代表窄栏到全屏，避免只验某个截图宽度 |
| 缩放 | 100%、125%、150%、200% 各记录有效视口；对200%完整支持的测试仍须提供至少320×400 CSS px有效视口。另测固定宿主窗口连续放大；若视口低于基线，明确记为尽力适配，不能靠缩小字体或逆向缩放恢复旧布局 | 放大后仍可读、能操作；不会把320宽窗口放大后的160有效宽度误记为完整支持要求 |
| 布局密度 | 保持一套可读字号层级；窄栏优先缩减横向间距与换行，宽栏增加留白，不用不同字号强行装满空间 | 不随着侧栏收窄变成更小的字 |
| 顶层导航 | 保留既有页签及顺序，窄栏允许换成两行；不把顶层页面改成抽屉或新导航结构 | 所有页面入口始终可见 |
| 看板工具区 | 既有分组保持，组与组换行；搜索独占可用行。非关键文字可保留既有图标提示，但键盘焦点、可访问名称不可丢 | 窄栏无需猜测图标意义或寻找消失入口 |
| Issue 操作 | 两个填入按钮仍在该票内，必要时整体移到标题下并各自换行；按钮文字保留，不能退化成难区分的两个图标 | 能明确区分当前聊天与新聊天 |
| 标题与标签 | 列表标题可保留两行摘要，但展开详情必须能读全；标签允许换行，不能用页面级横滚承载 | 摘要紧凑，内容仍可访问 |
| 正文/链接 | 详情正文自然换行；无空格长链接允许断行，复制及实际链接保持原值 | 不因长字符串挤出视口 |
| 文件路径/提交标识 | 行内摘要可截断显示，必须有可键盘操作的完整值查看或该行局部横滚；已有完整路径不重新截短 | 复制原值和辨识同名前缀目录仍可靠 |
| diff/代码 | 保留空白与行结构，允许自身横向滚动；外层不能被长行撑宽。行号与符号不能被换行误配 | 可对照 Git 变更，不把代码折成难读段落 |
| 滚动归属 | 当前页主要内容承担纵滚；顶层页签保持可达。去掉无价值的多层纵滚；diff、日志及长弹窗是明确的局部滚动例外 | 滚轮行为可预期 |
| 小高度 | 工具区和筛选区不得占据大部分视口；内容不足时允许它们随页滚动，关闭/返回操作保持可达 | 打开虚拟键盘或窗口压低时不会只剩工具栏 |
| 弹窗 | 边缘留白随容器压缩，最大宽高不超可用容器；标题、关闭和主要动作可达，长内容在弹窗内部滚动 | 不被固定 460/480 px 宽或超长表单卡住 |
| 反馈 | 底部 toast 按容器限宽，长文本断行，不遮挡当前输入和按钮；错误需有可再次查看的信息渠道 | 短反馈不改变列表行高，重要错误仍可读取 |
| 尺寸变化 | 用户编辑内容、已选 Issue、展开内容、活动页签保持；页面不因跨断点重新挂载并清空状态 | 拖动侧栏时能继续工作 |

这组规则已依用户本轮授权采用。实现断点按内容决定，以布局视口而非设备类型划分；320、380、480、640、960是测试样本，不是必须逐一写入CSS的断点。基准采集仍须查明宿主实际最窄尺寸，并补测该尺寸，不能据设计下限虚称宿主已达到320 px。原生宿主不能生成的尺寸在受控渲染中测试，并与原生结果分列。

## 测量和滚动约束

- 每份结果记录版本/资源指纹、页面/状态、布局视口宽高、`devicePixelRatio`、宿主缩放的实际设置及主题。DPR不能单独证明缩放百分比；浏览器测试的视口缩小可证明布局响应，但不能替代原生200%缩放验收。
- 页面级横向溢出以根文档和可见外壳的`scrollWidth ≤ clientWidth + 1 CSS px`检查，1 px仅容忍小数像素取整。还需目视/键盘检查无被`overflow:hidden`掩盖的按钮、文字或焦点环。局部代码/diff/路径滚动容器可超宽，必须受外壳宽度约束，能以键盘或原有查看入口读全。
- 正常高度：每个活动页面一个主要纵向滚动区，顶部导航保留。页面滚动不能再与等高外层滚动竞争；必要的diff、日志及弹窗内部区域是例外，需有可见边界且不会形成键盘陷阱。
- 低高度或多行导航：当固定区域妨碍显示内容或焦点时，释放固定高度/定位，让导航和工具区参与主要纵滚；顶部入口、返回/关闭/主要操作通过正常滚动或键盘可达，不要求所有操作同时驻留屏幕。弹窗只能有一处主要正文纵滚，底部动作可随内容滚动；禁止正文与整体各有一条同用途纵滚。
- 宽度改变允许文本重排导致绝对`scrollTop`变化，但不能主动重置到顶部；应保留阅读位置附近的内容锚点。活动页面、编辑值、焦点目标、选中项及展开状态保持。若焦点因重排离屏，应能滚动进入可见区，不能删除并重建输入节点来适配。
- 两个提示词填入出口保留文字、顺序、动作语义及可访问名称；窄栏换行/堆叠，不新增自动发送。顶层页签保留名称和顺序；现有内部页签的渐进显隐机制逐一核验，不能用通用选择器一并改变信息架构。
- Toast仍为底部短暂反馈。长文断行；显示时不得盖住焦点输入或正在操作的按钮。重要失败需能从既有错误/状态渠道再次查看，不能以新增消息面板或恢复旧草稿中转流程解决。

## 已核实的源码事实与实现风险

1. `prototypes/upstream-port/browser-runtime.mjs` 的 `PanelShell` 以 `mattskills-tabs` 装配五类页签，并用 `hidden` 保持各面板挂载；不要为了响应式重建活动页或改变条件挂载方式。
2. `prototypes/upstream-port/theme.css` 的 `.mattskills-tabs` 是无换行规则的 flex；每按钮有左右 10 px 内边距，英文导航更长。需在运行态确认窄栏总宽度，不能仅依据中文截图判定无溢出。
3. 上游 `vendor/mattskills-1.8.0-rc.7/lib/client.js` 的 `.dsws-tabs` 显式 `nowrap` 且 `overflow:hidden`，已有按优先级收起文字的渐进机制。不能粗暴对所有页签同一选择器覆盖，否则会改变现有操作入口的显隐行为。
4. 同文件 `.dsws-tt-wrap` 两行截断；长标题可见性必须同时验证详情和键盘操作，`title` 悬停不是完整可访问性的单独证据。
5. `.mattskills-tabpanel`、`.dsws-body`、沙箱任务 `section` 都可能拥有滚动。沙箱任务样式同时设 `height:100%`、padding 和 `overflow:auto`，需检查盒模型与嵌套纵滚；不要仅在最外层 `overflow:hidden` 掩盖内容丢失。
6. `direct-issue-actions-client.mjs` 已有 flex 换行、`minWidth:0` 和限宽 toast；适配应沿用当前双按钮结构，不恢复旧动作出口。toast 固定右下位置需要检验窄栏和低高度的遮挡。
7. 版本管理已有 `min-width:0`、`max-width:100%`、diff 的 `white-space:pre` 和局部 `overflow:auto`；路径也已有局部滚动。应以实际内容边界回归，避免通用 `overflow-wrap:anywhere` 破坏 diff 行。
8. 上游通用弹窗 CSS 的固定宽度与 `max-width:94vw` 并存，多处还使用内联宽高。必须核对 `vw/vh` 在插件 iframe 中对应的实际视口及 padding/box-sizing，单改通用 class 不保证所有弹窗获益。
9. 本决议不添加术语或 ADR；属于可调整的布局规则，没有难逆转的领域决定。无产品样式修改、宿主操作或原生验收结论。

## 实施验收矩阵

以下是未来实施必须通过的标准，本决议没有执行这些产品测试。先在受控环境遍历矩阵，再在当前宿主可达到的布局/缩放中核验并单列结果。

| 组别 | 场景 | 通过条件 |
| --- | --- | --- |
| 尺寸/主题 | 320、380、480、640、960及宿主全屏实际宽度，常规高度和400 CSS px高度；明暗各测；不足400高另测低高度回退 | 无页面级横向溢出；导航、返回/关闭、主要操作可通过滚动和键盘到达；不靠缩小字号 |
| 缩放 | 原生100%、125%、150%、200%，记录每次有效视口；完整支持样本不低于320×400；另测窗口固定时连续放大 | ≥基线满足全部布局标准；低于基线单列限制，不混报失败或通过；输入值/选择/焦点保持 |
| 长内容 | 中英文长标题、密集标签、无空格链接、同前缀长路径、长diff、日志、长表单 | 摘要有读全路径，链接与复制原值不变；diff保留行/空白；长内容仅在指定局部横滚 |
| 页面/状态 | 实际存在的全部顶层页、看板列表/详情/版本管理、实际弹窗；加载/空白/错误/禁用/成功 | 逐页核对继承的结构与操作；不可到达或未测页面明确列缺项，不能以一个列表截图代表全插件 |
| 状态保留 | 640→320→640连续调整；各断点前后；编辑中/已选Issue/展开内容/活动页/焦点与阅读锚点 | 不重置、不无故重挂载；焦点可见或能正常滚动到达；无意外失焦或键盘陷阱 |
| 反馈/弹窗 | 窄栏、400高及低高度；长错误、底部按钮、打开长弹窗后键盘遍历 | 正文和主要操作不裁切；反馈不盖住当前操作；关闭后焦点回到原入口 |

高度低于400 CSS px的回退以200 CSS px为受控冒烟样本；更小尺寸不承诺完整展示，但不得清空用户编辑状态。无法在实际宿主复现的样本须明确标记受控证据。动态主题切换的帧级颜色/闪烁标准继续等待独立主题调查，静态明暗布局不受其阻塞。

## 交接与状态

响应式设计问题已收口：采用320×400有效CSS视口基线、200%缩放语义、内容驱动换行/堆叠、保留双文字出口、页面主要纵滚与明确局部横滚例外。视觉字号/颜色/间距的具体值由整体原型基于有效宿主基准决定，不能在本票预填。

下一阶段将本决议作为视觉原型和实施规格输入。此票完成不等于视觉基准采集完成，不解除原型对基准的依赖，也不解除最终验收对主题调查的依赖。普通实施票由主代理纳入地图；是否运行服务切换/发布另依用户授权判断。

## 场景速查

- 320 px 窄栏：超长中英文标题、两按钮、多个标签、五页签、版本管理长路径、长 diff、长弹窗；全部动作通过键盘可达，无页面级横向溢出。
- 宽度从 640 px 连续拖到 320 px 再恢复：编辑文本、选中项、展开内容与活动页不丢失；滚动位置不无故跳到顶部。
- 200% 缩放与 400 px 高度：页签、主要内容和弹窗关闭/提交可达；toast 不遮住当前操作。
- 明暗及错误/空白/加载状态保持同一布局规则；主题闪烁仍由既有独立调查提供结论。
