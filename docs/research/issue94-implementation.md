## 实现

在适配层把版本管理独立皮肤令牌映射到主体共享背景、文字、边框和交互色。普通按钮/输入/选择控件采用主体字体、12px 字号、6px 圆角和同一焦点样式；行距、控件高度和普通文案字号不再随明暗变化。保留原组件、分区、文件行、历史/工作树视图和 Git 专用等宽字体，新增/删除/冲突等语义色不改成普通主按钮色。

完整文件路径和工作目录路径不在模型层缩成省略字符串；适配构建只替换三个唯一源码锚点（锚点漂移失败），在现有行内提供独立滚动区域。diff 保留等宽与行结构，超长行在补丁内容区滚动，不扩大侧栏。不修改 vendor、不新增 Git 后端契约。

## Red → green 与命令

`node build.mjs`（从 `prototypes/upstream-port` 执行）生成待测真实客户端，`node verify-version-control-style.mjs` 用 Chromium 真实布局引擎加载生产渲染器，仅替代宿主 RPC 边界。

首个有效 red：普通版本管理按钮的计算结果为 Arial/10px/2px 圆角/28px 高，主体参考控件为 Arial/12px/6px 圆角/25px 高。随后真实浏览器另发现 diff 子行内联 `pre-wrap` 导致长行换行，以及文件路径在模型层已被截短；各自以实际内容可读性断言确认失败后修复。

最终受控结果：

| 矩阵 | 场景 | 结果 |
| --- | --- | --- |
| T8 | 浅/深普通按钮和输入字体/字号/圆角/高度 | 通过：与主体控件合同一致，按钮和输入均 26px 高，双向换肤不变 |

Chrome 窗口最小宽度会夹到约 512px，因此测试明确固定并**实测**侧栏内容宽度 320、380、760px，同时单独报告 `innerWidth`（512、512、838），不把请求窗口宽度冒充实际侧栏宽度。Headless 虚拟时间可能暂停合成帧，测试只把 requestAnimationFrame 调度替换为 16ms 定时器；ResizeObserver、样式计算、字体、几何与滚动仍由真实浏览器执行。
