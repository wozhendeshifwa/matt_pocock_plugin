# #88 直接填入的变化保护与恢复

本票在独立分支 `codex/issue88-recovery` 上从集成 `c161195` 开始，实施前同步 #89 的 `ea6a0ff`，结束前合入 #90 所在集成 `e6ec732`。保留主工作区预存修改、旧草稿及 #70 标准，未改配置／服务／GitHub，未操作真实宿主草稿或发送消息。

## 已实现的完整行为

- 来源／规则变化先停，按钮旁明确提供按最新来源重新生成；必要条件仍缺失时停止，补齐后重新核验及明确再生成。
- 发送前重新读取 Issue 动作依据，仅当推荐动作实质变化时停止并要求再次点击；无关标签不打断，手选补充动作仍使用显式上下文。
- 在点击时捕获来源目标，跨异步准备期间继续校验。重试／再生成保留原操作目标，不静默改投后来切换的聊天。当前原生与受控可靠适配器均可消费该来源约束，未假造原子宿主能力。
- 共享等待状态按侧栏元素隔离并跨该侧栏的项目重挂载保留，暂停其他 Issue／更多动作注入及工具栏注入。共享宿主出口同时拒绝竞争请求；浏览、正常复制及历史原文复制仍可主动使用。没有跨窗口全局去重。
- 反馈写入原 Issue 的记录；浏览其他票不会承接旧反馈，返回原票能看到完成结果。复制结果和正在等待的注入反馈分开，更多动作的复制不会偷换成主动作文本。
- 请求已发后 transport timeout／丢失回执及可观察到的意外项目／目录变化按未知处理；宿主明确拒绝仍是失败。正常新聊天导航仅显示已请求，不宣称可靠填入。
- 未知结果提供先检查原输入框的提醒，用户明确确认后才重新核验并重试。失败文本保留供主动复制，复制保留文本不重新生成；普通来源变化后的明确复制再生成仍保持复制出口，不改投聊天。
- 保留 #89 的请求覆盖接口和来源快照所属 preparation 实例检查；保留 #90 的历史原文取回（包括等待期间可主动复制）。旧面板最终删除和布局收口仍由 #91 承担。

## TDD 证据与接缝

只使用既定的生产侧栏 UI → 来源准备／宿主草稿／剪贴板边界。宿主、来源、GitHub 读取、时间／延迟是受控边界；测试不读私有 React 状态、Map 或内部协调器方法。宿主侧使用实际原生适配器，观察其发出的请求；不通过替身拼接输入文字证明原生空行。

逐场景 red → green 捕获并修正：

1. 来源变化后缺少明确再生成入口。
2. 其他票仍可竞争注入、主动复制被等待状态禁用。
3. 准备期间切换聊天后，旧点击被静默投向新聊天。
4. 已发请求的 transport timeout 被误报为确定失败，且缺少未知重试前检查。
5. 相关标签变化仍发送旧推荐动作。
6. 必要资料补齐后旧失败快照无法恢复。
7. 新聊天请求后切到另一项目仍显示普通请求成功反馈。
8. 等待期间复制另一个补充动作却得到主动作文本。
9. 同侧栏工具栏仍允许竞争注入。
10. 未知结果重试静默转投后来切换的聊天。
11. 明确重新生成复制时又回用旧注入来源快照，无法完成复制恢复。

恢复脚本含 18 组生产 UI 场景，覆盖列表／详情来源变化、同侧栏等待、复制、准备前后目标变化、未知／明确失败、相关／无关标签、必要条件恢复、浏览换票反馈归属、正常新聊天导航、更多动作复制及原目标重试。另外为原直接动作脚本补 native-only 出口误报 filled 时仍降为 requested 的 UI 场景。
