# 补充动作与技能菜单验收

对应 [补充动作推荐与全部技能菜单](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/69)，策略依据为[动作规格](https://github.com/wozhendeshifwa/matt_pocock_plugin/issues/60)。

## 已实现及自动化证据

`npm run check:issue-actions` 通过，包含生产构建后的 React 动作点击、可编辑预览及三出口高层行为检查；原有项目身份、send:false 桥接及 27 技能／46 双语模板回归通过。

- 第一轮：发送请求中包含“仅生成草稿／不自动执行”会取消接收 Agent 的任务，高层断言先失败；移除该 UI 专属句后通过。面板仍仅填入草稿，不自动发送。
- 第二轮：补充动作及全部菜单不存在的高层检查先失败；接入预览选择器后通过。
- 默认标签主动作保持独立；没有上下文时不推荐 PR、retro 或 code-review。ready-for-agent 不作为推荐依据，推荐函数不读取关闭状态。
- 用户明确提供范围及分支／PR后推荐 PR；生成 Summary、Evidence、Merge Danger 正文草稿，缺验证如实记录，禁止自动发布、创建 PR、推送及合并。缺范围／分支时仅生成查证请求。
- 用户明确提供基线及范围后推荐 code-review，允许进行中改动；缺基线先查证，不猜 main 或当前分支，修复进入 implement-spec。
- 用户明确提供目标编码会话、原始记录及结束／失败／中止／返工等观察后推荐 retro；缺会话或原始记录先查证，不默认当前会话。先给改进候选，由用户选择。
- 保留全部 27 项技能手动菜单；implement 仅手动可选，不推荐为代码入口。切动作将覆盖已编辑草稿时确认，取消保留原文。
- 补充动作／手动技能也复用同一可编辑文本和 active、new、copy 三出口，高层测试验证编辑后最终文本一致。

## 限制与交接

- 当前补充上下文来自用户明确填写的预览字段，初始不推定项目当前分支或聊天；未声称已有可靠的宿主会话／Git上下文解析。关联上下文规格可复用本请求与推荐规则接入其来源。
- 轻量预览是原生产动作的适配，不是最终 B 底部动作栏。后续底栏可替换视图，但应复用同一主动作及补充请求规则。
- 自动化通过不证明真实宿主路由、系统剪贴板或 Agent 实际执行正确。真实宿主输入保护、目标变化保护和会话证据仍由关联交互／验收工作收口；本轮未安装、部署或更新技能。
