# MattSkillsDeck 1.8.0-rc.7 host service contract

Verified 2026-11-06 by static inspection of the installed-version copy in `vendor/mattskills-1.8.0-rc.7`. No upstream host execution. Paths and line numbers below are relative to that directory; they describe actual consumers, not a complete DSH SDK specification. Preserve these services behind a Codex adapter and preserve upstream UI/RPC behavior.

## Apply is not a side-effect-free registration

- Apply launches bootstrap and refresh wiring immediately (`lib/index.js:93`). Bootstrap scans skill locations and registers a skills provider (`lib/bootstrap.js:22–76,183`). Refresh attaches session/tool event listeners and registers seven deck tools (`lib/refresh/wiring.js:71,294–309`; `lib/refresh/writeEvents.js:377–389`). Event signatures are `(session,event)` for `session/event` and `(exec,result)` for `tools/result`.
- Apply loads the logging switch and emits startup log state (`lib/index.js:320`; `lib/logStore.js:220–229`). This can lead to log persistence through the ordinary buffered log path.
- Apply starts naming guardian events (`lib/index.js:330`). This schedules a sweep and an immediate one-repository fallback; existing saved watches can trigger repository queries and state persistence. It is event driven, not a permanent polling loop (`lib/namingGuardian.js:20–64`).
- Upstream registers the RPC route as part of startup (`lib/index.js:333`; `lib/rpcChannel.js:156–179`). A host shim can capture the registered fetch handler and invoke it through MCP without opening an HTTP port.

## Isolating Codex data from DSH

**Inject platform before apply, and isolate actual process cwd. Both are needed.** `ctx.get('platform')` wins when it exposes `getHome()` and `path` (`lib/platformChannel.js:106–107`). Provide the complete platform object: os, getHome, path helpers, resolveExecutable, fs, env and explicit openFolder/openFile actions (`lib/platform/index.js:61–90,176–185`). Windows home must be an absolute drive path; createPlatform can use supplied homedir/env (`lib/platform/win32/index.js:22–60`).

1. Choice storage is `<getHome()>/.dsh/mattskillsdeck/choices.json`; it uses **node:fs/promises directly**, not the DSH fs adapter. Its injectable fs is not supplied by platformChannel's constructor. Point platform.getHome to a dedicated Codex-owned data root before initialization. This retains original internal filenames beneath a separate root (`lib/choiceStore.js:7–23,35–37,184–189`; `lib/platformChannel.js:332–335`).
2. Cache storage is **actual `process.cwd()/.dsh-mattskillsdeck-cache`**, regardless of getHome. Start a dedicated host process in its own Codex data directory; pass the real project cwd explicitly in each operation. Do not change cwd of the shared desktop process (`lib/repoKeys.js:251–259`). Naming state also uses that cache (`lib/namingGuardian.js:15,25–46`). Session-ticket persistence has a direct node-fs fallback, so intercepting fs.resolve alone is insufficient (`lib/refresh/sessionTickets.js:36,77–99`).
3. Bootstrap does **not** resolve bundled skills relative to its module. Candidates begin with cwd/package/bundled-skills, parents, cwd/bundled-skills and ancestor node_modules; fallback scans **real `os.homedir()/.dsh/profiles`**, bypassing injected getHome. Supply the intended bundled-skills folder in the isolated cwd or explicitly adapt the discovery seam to the vendored folder. Do not allow accidental selection of the user's DSH installation (`lib/bootstrap.js:22–64`).
4. Install adapters and service lifecycles before apply, initialize with a clean isolated naming/cache state, then enable original events only when mapped to real Codex project/session events. This avoids inherited DSH watches. Do not suppress upstream functionality permanently to hide a missing adapter.

## Remaining integration boundary

This note proves host service call shapes, not native Codex project/session bridge availability. The complementary `codex-host-contract.md` distinguishes documented UI message support, CLI app-server session APIs and unverified desktop inheritance/progress paths. Native project identity must be supplied per panel/session; the isolated host process cwd is a storage location, never the active project's identity. This preserves ADR-0001's project isolation without treating a CLI exec run as proof of a native desktop task conversation.
