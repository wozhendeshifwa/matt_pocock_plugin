# 技能来源与只读备用边界

实现范围：来源规格中的技能目录、正文、当前项目来源以及只读备用；不安装或更新真实用户技能。

`createSkillsService` 的目录默认固定为插件的 27 项。`get`、`inspectForUse` 和 `readDoc` 共享来源选择；`resolveBinding` 在本地正文缺失时仍可返回同项目宿主提供的既有绑定，供后续修复使用。

可信宿主可提供 `resolveHostSkill({name, projectRoot})`，返回 `path`、`projectRoot`、`sourceId`、`binding`。项目须与当前服务的真实路径一致，正文的技能名也须匹配。没有该通道时不会搜索用户目录或以文件时间猜来源，显示随包参考及未知宿主来源。`actualLoad` 保持 `unknown`：解析到正文也不是实际加载证明。

正文差异去除 BOM、换行和行尾空白后比较，不对不同正文做兼容性猜测；两份正文供 Agent 结合用户明确规则判断，兼容差异可自主继续，实质决策冲突才澄清。

备用核验会读取技能全文及正文中的相对文件链接，递归读取 Markdown 引用；代码围栏中的示例、外部链接和锚点不作为本地依赖。越界、不可读、超限引用暂停依赖步骤。文件链接扫描无法理解所有自然语言前置条件，因此还要求可信 `assessRequirements({name, projectRoot, documents})` 返回完整核验及逐项工具可用性；通道缺失或不完整时如实待核验。它不会禁止生成可编辑的查证请求，不会替 Agent 回答实质决策。

当前 MCP transport 只提供项目/会话身份及宿主草稿能力，没有当前宿主的技能解析、工具要求评估或实际加载证据通道。生产默认以参考展示，依赖步骤标为待核验；不把另起 Codex 进程当成当前宿主。真实宿主来源与实际会话使用仍待验收，不能用受控 resolver 测试宣称已经加载。

`node-host` 已将真实 `skill.readDoc` 接到本服务，并修正检查链：随包正文可读不再显示为宿主安装通过。客户端适配 `adaptSkillSourceDisplay` 增加目录来源提示并取消按技能名跨项目缓存详情，需由构建链调用。原始 vendor 文件未修改。

验证使用已确认的技能高层边界：临时目录及可信宿主替身覆盖来源选择、错误项目、格式/行为差异、缺引用、缺工具、完整只读备用、既有绑定保留；真实 MCP 服务及 jsdom 检查目录、来源正文和待核验检查链。它们不证明当前 Codex 聊天实际加载。
