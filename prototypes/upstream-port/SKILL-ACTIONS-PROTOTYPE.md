# #57 技能动作交互原型（THROWAWAY）

## 问题与分支

问题：在现有 Issue 详情中如何呈现动作、推荐、上下文与草稿出口，使用户容易发现下一步并看清点击结果？

采用 prototype 的 UI 分支：同一路由 `/`，以 `?variant=A|B|C` 和底部悬浮切换条比较三种结构；不重做原版周边界面。

## 用户选择（2026-11-26）

用户最终选择 **B 底部动作栏**，原话：“底部动作栏也挺好，非要我选一个的话，底部动作栏吧”。此前“回归原版”和 A 偏好已被这次选择覆盖。用户未额外陈述选择理由，不替用户补理由。

B 在详情底部显示当前主动作及上下文提示，点击“选择动作 / 预览”展开动作、补充动作、全部技能、必要上下文与缺项、技能来源提示、可编辑草稿及三个出口；可以收起。A 详情内联和 C 分步面板作为比较证据保留。本结论选择交互方向，不证明生产实现或真实宿主验收已完成。

## 运行与比较

已有依赖的仓库内运行：

```powershell
node prototypes/upstream-port/preview-skill-actions-prototype.mjs
```

新检出归档分支时，先运行 `npm ci --prefix prototypes/upstream-port` 安装该目录锁文件中的依赖，再运行上面的命令。

打开 `http://127.0.0.1:43157/?variant=B`；A/B/C 参数可分享，刷新保持布局。悬浮条箭头和键盘左右键切换，编辑控件中的箭头不切换。场景参数为 `case=prototype|implement|missing|bug|none|pr|retro|conflict`。

所有案例、技能状态、宿主出口与剪贴板均为内存模拟。输出完整文本在页面状态的 `lastOutput.text` 中；没有真实创建聊天、发送、复制系统剪贴板或更新技能。场景控制及状态检查器不是生产界面。

## 核验与局限

- 启动与内存构建成功；浏览器已显示复用原版的 Issue 详情和 B 展开面板。
- 在 380px 侧栏对同一份审查草稿点击当前聊天、新聊天、复制，页面状态分别记录 active/new/copy，文本一致、`send:false`、`simulated:true`。
- 覆盖正常实施、缺规格与票图、needs-info + bug、wontfix 无默认实施动作、PR 缺验证证据、retro 未定位会话、地图角色冲突；来源状态含待确认、完整随包备用、更新失败保留可用版本、无可用来源及必要工具缺失。
- 上述场景可操作，不将其列为全部已完成真人验收。无测试套件，符合抛弃式原型规则。
- 实现时须重新按生产标准实现；底部面板的定位、遮挡、宿主可用空间及真实草稿路由应在 #58 的验收与实施交接中确定并验证。
